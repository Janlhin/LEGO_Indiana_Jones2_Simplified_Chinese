## 待评估

- [ ] 🈶 **繁体中文变体。** 评估结论：**可行，但成本集中在字体，不在文本。**

  ### 前提：简繁不能共存，只能二选一

  游戏的语言由注册表 `LanguageVal`（Windows LANGID）决定，中文是**借用日语槽位
  1041** 实现的 —— 那是游戏唯一的多字节文本通路（`japanese.txt` + 一套 CJK 字体），
  见 `tools/set_language.py`。英语发行包的 `32450_install.vdf` 只声明了 5 个语言槽
  （英 1033 / 法 1036 / 德 1031 / 意 1040 / 西 1034），**没有中文槽**。

  所以繁体**没有独立槽位可挂**。想做，只有两条路：

  1. **另一个独立补丁包**（与简体二选一）—— 现实可行，代价见下。
  2. **改引擎**加一个真正的简/繁切换 —— 要动 exe 与语言表，工作量远超收益。

  ### 成本拆解

  | 层 | 难度 | 说明 |
  | --- | --- | --- |
  | 文本 | 中等 | 1952 行简体译文转繁体。机械转换可自动化（简繁对照表 / OpenCC），但**人工审校是主体**：一简对多繁（发→發/髮、干→乾/幹/干、里→裡/里）；两岸术语差异（软件→軟體、界面→介面、鼠标→滑鼠、信息→資訊、默认→預設）；章节 / 角色 / 单位等专名要统一。粗估 **30–60 小时** |
  | **字体** | **最高** | 中文字体是**重写进 DAT** 的（`gui/Font/FONT_NXG.FT2`、`stuff/text/FONT2_NXG.FT2`、`gui/Font/font_pc.fnt`），繁体要另一套字形：得找字形完整且**授权可用**的繁体字体（标楷体 / 华文楷体一类；项目目前走 ctypes 调 GDI32 栅格化系统楷体）；重跑 `build_font.py` → `build_ft2.py` → `rebuild_dat.py`（改写 4 处头部字段）；再重跑 `fix_font_coverage.py` —— 繁体用字集不同，缺字情况会变（简体版当初就缺 441 字，排查很花时间）。粗估 **1–3 天** |
  | DAT | 低 | `rebuild_dat.py` 现成，流程不改，只是换成繁体载荷 |
  | 分发 | 低 | 另一套分卷包；工具链已经能打，脚本不用改 |

  ### 结论

  **合计约 1–2 周（含人工审校），换来的是"二选一"，不是"多一个选项"。**

  如果目标只是"让繁体玩家也能玩"，性价比更高的做法是**先做文本层 + 字体层，
  但字体只覆盖 UI 实际用到的字**（拿现有 `fix_font_coverage.py` 的用字集反推），
  遇到生僻字再逐个补 —— 避免为 2124 行里从不出现的字也去凑字形。

  待定：是否要做、以哪个为主线（简体为主 / 繁体为主）。
